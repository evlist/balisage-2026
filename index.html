Same content, different audiences...

rings a bell in markup heads !

Wordpress serves HTML and CSS print is available.

But CSS can't change the structure of the content.

CSS print is not enough.

That's why XSLT has been invented.

Wordpress doesn't use XSLT.

In 2018, Wordpress introduced block (and page) templates.

Yes, I said "templates", like in <xsl:template/>.

Wordpress templates are written in PHP and HTML.

They can be used to create different presentations of the same content.

So, I hacked Wordpress to use different templates for web and print.

The server doesn't know if the client wants a print version unless we say so.

I did it with a "?print" query string.

A PHP hack selects a page template with a "-print" suffix when "?print" is detected.

Completely different presentations can be then presented for web and print.

Print pages are then exported to PDF and assembled manually into books.

Current and future directions

Package these hacks into proper plugins.

Automate what can be automated.

Game changer

It could also generate content for different audiences (friends, relatives, mother).
